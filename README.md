# Hey DJ

> A fully self-hosted AI radio DJ. Your local music library, an on-device LLM, and a neural TTS voice — streamed live to any browser. **Zero cloud. Zero subscriptions.**

The DJ picks songs based on mood, generates natural commentary between tracks using a local LLM, speaks it aloud via Kokoro TTS, and streams the combined audio to your browser or Android PWA. Skip a track and the DJ introduces the next one.

---

## Features

- 🎵 Streams MP3, FLAC, OGG, WAV, M4A, AAC from a local folder
- 🗣️ Natural DJ commentary via **Kokoro TTS** (on-device, ~120 MB ONNX model)
- 🤖 Commentary text generated by **Ollama** (fully local LLM — no API keys)
- ☁️ Optional **OpenAI-compatible** LLM provider (OpenRouter, Groq, Together.ai, LM Studio, etc.) — swap at runtime from Settings
- 🎭 6 DJ presets: Smooth, Hype, Late Night, Morning, Focus, Café
- 🎨 6 moods that shape track selection: Chill, Hype, Focus, Party, Late Night, Morning
- 🎤 Custom instructions to the DJ ("only talk about the artist's history", "keep it brief")
- 🔢 Frequency control — DJ every song, every 2nd, 3rd, or 5th
- 🔍 **Song search** — search by title, artist, or album with field-specific filter tabs; genre dropdown updates live with results
- 🎶 **Queue management** — add songs, remove individual items, clear the queue; live count badge in nav
- 📋 **Playlists** — create, rename, delete playlists; add tracks from the Library; queue an entire playlist with one tap
- 📺 **Embeddable widget** — compact `<iframe>` player for any website, configurable size and backend URL
- 📱 **PWA** — installable on Android via Chrome "Add to Home Screen"
- 📊 Listener stats & session history
- 🖼️ **Album art** — displays embedded cover art from your files; falls back to MusicBrainz Cover Art Archive automatically (no API key)
- 📝 **Lyrics** — auto-displayed on Now Playing; dual-source lookup: lyrics.ovh → LRCLIB fallback for multilingual & obscure tracks (both free, no API key)
- 🎶 **Audio visualizer** — live frequency bars or waveform synced to the stream
- � Real-time sync across multiple browser tabs/devices via WebSocket

## Hardware Requirements

The only computationally expensive parts are the LLM (commentary text) and TTS (speech). Audio streaming is negligible.

### Minimum — functional, DJ speaks on natural transitions
| Component | Spec |
|-----------|------|
| CPU | Any modern x86_64, 4+ cores (2018 or newer) |
| RAM | **8 GB** — model ~2.5 GB, TTS ~300 MB, OS ~2 GB |
| GPU | None required |
| Storage | 3 GB free (models + DB) |
| Network | 100 Mbps LAN if music is on a NAS |
| OS | Linux (Ubuntu 20.04+), macOS 12+, Windows WSL2 |

> ⚠️ On minimum hardware, LLM generation takes 8–15 s. The DJ will speak reliably at **natural track endings** (45 s prep window) but may time out on rapid skips.

### Recommended — DJ speaks on every skip, under 2 s latency
| Component | Spec |
|-----------|------|
| CPU | 8+ cores (Ryzen 7 5800X / i7-12th gen+) |
| RAM | **16 GB+** |
| GPU | NVIDIA **6 GB+ VRAM** (RTX 3060 / 4060 or better) — Ollama uses CUDA automatically |
| Storage | NVMe SSD |
| Network | Gigabit LAN |

> With a GPU, LLM drops to ~1–2 s. Combined with TTS (~0.5 s), total commentary generation fits comfortably in the 2 s skip window.

### Faster LLM option
If you have limited RAM or no GPU, swap to a smaller model — quality is nearly identical for 30-word DJ intros:
```bash
ollama pull llama3.2:1b   # 1.3 GB, 2–4 s on CPU
```
Then set `OLLAMA_MODEL=llama3.2:1b` in `.env`.

### Using a cloud / third-party LLM

You can swap to any **OpenAI-compatible** API from the **Settings → AI Provider** section at runtime — no restart needed.

| Provider | Base URL | Notes |
|----------|----------|-------|
| [OpenRouter](https://openrouter.ai) | `https://openrouter.ai/api` | Many free & paid models, generous free tier |
| [Groq](https://groq.com) | `https://api.groq.com/openai` | Very fast inference, free tier available |
| [Together.ai](https://together.ai) | `https://api.together.xyz` | Wide model selection |
| [LM Studio](https://lmstudio.ai) | `http://localhost:1234/v1` | Local alternative to Ollama |
| OpenAI | `https://api.openai.com` | `gpt-4o-mini` works well and is cheap |

In Settings, select **OpenAI-compatible**, enter the base URL, your API key, and the model name. The DJ will use it immediately for the next commentary generation.

## Installation

### 1 — Clone & configure

```bash
git clone https://github.com/curlyphries/hey-dj.git
cd hey-dj

cp .env.example .env
# Open .env and set MUSIC_DIR to your music folder path
```

### 2 — Pull an LLM

```bash
ollama pull llama3.2:3b        # ~2 GB, best quality
# OR on low-RAM / CPU-only machines:
ollama pull llama3.2:1b        # ~1.3 GB, nearly as good for short text
```

### 3 — Backend

```bash
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

**First run** downloads Kokoro ONNX model files from Hugging Face (~120 MB). This happens once and is cached in `backend/`.

### 4 — Frontend

```bash
cd frontend
npm install

# Production build (served by FastAPI at http://localhost:PORT)
npm run build

# OR live dev server with hot-reload (at http://localhost:5173)
npm run dev
```

Open **`http://localhost:8000`** (or your configured `PORT`).

## Quick Start (Docker)

Requires Docker + Docker Compose. **Ollama must be running on the host** — the container reaches it via `host.docker.internal`.

```bash
cp .env.example .env
# Edit MUSIC_DIR in .env

docker compose up -d
```

Open **`http://localhost:8000`**

> Model files are downloaded inside the container on first start (~120 MB). To persist them across rebuilds, add a named volume for `/app` in `docker-compose.yml`.

## Customising the DJ

Go to **Settings** in the app. From there you can:

- **Toggle the DJ on/off** without restarting
- **Set frequency** — every song, every 2nd, 3rd, or 5th track
- **Apply a preset** (Smooth, Hype, Late Night, Morning, Focus, Café) — sets persona + mood + style instructions in one tap
- **Choose intro style** — Classic (tight radio segue), Artist-led, Genre-led, or Vibe/feeling-led
- **Write custom instructions** that are injected directly into the LLM prompt, e.g.:
  - *"Tell me one interesting fact about the artist every time"*
  - *"Only play 90s R&B tonight and keep commentary short"*
  - *"I'm feeling melancholy — reflect that in the tone"*

The DJ commentary prompt template lives in `backend/src/llm/templates.py` if you want to edit the base prompt structure.

## Remote Access

### Nginx reverse proxy (recommended)

```nginx
server {
    listen 80;
    server_name dj.yourdomain.com;

    location / {
        proxy_pass http://localhost:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_buffering off;      # essential for audio streaming
        proxy_read_timeout 3600;  # keep stream connections alive
    }
}
```

Add HTTPS via `certbot --nginx`, then set `CORS_ORIGINS=https://dj.yourdomain.com` in `.env`.

### Android PWA install

1. Open **Chrome** on Android, navigate to your server URL
2. Tap ⋮ → **"Add to Home Screen"** → **"Install"**

The app opens full-screen with no browser chrome, indistinguishable from a native app.

## Architecture

```
Browser ──► GET /stream ──────────────────────────────────────────────────────┐
                                                                              │
Browser ──► WS /ws ──► WebSocket Hub ◄─── broadcast ◄── DJ Orchestrator      │
                                                              │               │
                                              ┌───────────────┤               │
                                              │               │               │
                                        Queue Manager    Mood Selector        │
                                         (SQLite)       (genre/BPM fit)       │
                                              │                               │
                                    ┌─────────┴──────────┐                   │
                                    │                    │                   │
                               Ollama LLM           Kokoro TTS              │
                            (commentary text)    (WAV synthesis)            │
                                    │                    │                   │
                                    └────────┬───────────┘                   │
                                             │                               │
                                      MP3 bytes (transition)                 │
                                             │                               │
                              Stream generator serves: ◄────────────────────┘
                              [commentary MP3] → [track file at realtime rate]
```

## FAQ

**Do I need an internet connection to run this?**
Only for the initial Kokoro model download (~120 MB, one-time). After that the entire stack — LLM, TTS, streaming — runs fully offline. The exception is if you configure a cloud LLM provider (OpenRouter, Groq, etc.) in Settings.

---

**How many people can listen at the same time?**
Network bandwidth is the only real limit, not CPU/RAM/GPU. Each listener costs ~24 KB/s (192 kbps MP3). On a gigabit LAN you can serve hundreds of simultaneous listeners from a basic machine. Over a home internet connection with 50 Mbps upload, that's ~260 remote listeners before the pipe fills up. The DJ commentary generation runs once per track transition regardless of how many people are listening.

---

**The DJ isn't speaking — why?**
The most common causes: Ollama isn't running (`ollama serve`), the model isn't pulled (`ollama pull llama3.2:3b`), or the DJ toggle is off in Settings. On slow/CPU-only hardware, skip commentary may time out — the DJ still speaks at natural track endings. See [TROUBLESHOOTING.md](TROUBLESHOOTING.md) for step-by-step diagnostics.

---

**Can I use a cloud AI instead of running Ollama locally?**
Yes. Go to **Settings → AI Provider**, switch to **OpenAI-compatible**, and enter your provider's base URL, model name, and API key. Works with OpenRouter (free tier available), Groq, Together.ai, LM Studio, OpenAI, and anything else that speaks the OpenAI completions API. Changes take effect immediately — no restart needed.

---

**Does it work on Windows?**
Yes, via WSL2 (Windows Subsystem for Linux). Run the backend inside WSL2 with Ubuntu, and access the web UI from your Windows browser at `http://localhost:PORT`. Native Windows is not tested.

---

**Can I use music from a NAS or network share?**
Yes — set `MUSIC_DIR` to the mount point. SSHFS, SMB, and NFS mounts all work. Under very high listener counts (50+), simultaneous reads from a slow NAS can cause I/O contention; local disk is preferable in that case.

---

**How do I change the DJ's voice or speed?**
Set `KOKORO_VOICE` and `KOKORO_SPEED` in `.env` and restart the backend. Available voices: `af_heart` (default), `af_bella`, `af_sky`, `am_michael`, `am_adam`. Speed range: `0.8` (slower/clearer) to `1.3` (faster).

---

**Can I add my own DJ persona or mood?**
Yes — edit `backend/src/llm/templates.py` directly. `PERSONA_MODIFIERS` is a plain dict of persona name → style instruction string. `MOOD_CONTEXT` maps mood names to atmosphere descriptions. Add entries to either dict and they'll appear in the UI dropdowns automatically.

---

**The stream restarts every time I skip — is that normal?**
Yes, by design. Skipping sends a signal to the backend, then the frontend polls until the backend confirms the next track is playing before reconnecting the audio stream. This ensures you always hear the new track rather than the tail of the previous one. The reconnect is typically under a second and should be seamless.

---

**Will my listening history / stats survive a server restart?**
Yes. Everything is stored in a SQLite database at `DATA_DIR/dj.db` (default `./data/dj.db`). Stats, play counts, session history, playlists, and the queue all persist across restarts. Runtime settings (DJ enabled, LLM provider, etc.) are in-memory and reset to `.env` defaults on restart — set your preferred defaults in `.env`.

---

**How does song search work?**
The Library page has four search modes selectable with tab buttons: **All** (searches title, artist, and album simultaneously), **Title**, **Artist**, and **Album**. Typing in the search box filters results live with a 200 ms debounce. The genre dropdown updates automatically to show only genres present in the current results. Clicking an artist or album name in a result row switches to that filter automatically.

---

**How do I add a song to the queue vs. a playlist?**
- **Queue** — the live play order. Songs in the queue play next in sequence, ahead of the DJ's auto-selection. Use the **Add to Queue** button in Library or the search box on the Queue page. Queue changes are broadcast live to all listeners.
- **Playlist** — a saved list you curate over time. Use the bookmark icon (🔖) in Library to add a track to any playlist. From the Playlists page, tap **Play All** to push the entire playlist to the queue at once.

---

**How do I embed the player on another website?**
Go to **Settings → Embed Widget**. Choose a size (Mini 320×60, Standard 480×90, Full 600×110), optionally set a label and backend URL, then copy the generated `<iframe>` code and paste it into any HTML page. Visitors on that page will see the live "Now Playing" info and a mute/unmute button. They need network access to your server's `/stream` endpoint to hear the audio.

---

**Can the widget connect to a server on a different host?**
Yes. In **Settings → Embed Widget**, enter your server's full URL in the **Backend URL** field (e.g. `http://192.168.1.5:8001` or `https://dj.yourdomain.com`). The generated iframe code includes a `?backend=` parameter so the widget's WebSocket and audio stream point to the correct server. CORS is set to `*` by default so cross-origin embedding works out of the box.
